### 🚀 What's New

**使用桌面宠物的 macOS 用户请升级：1.16.20 里宠物在重启 App 后不会回来，这一版修复。** 从 1.16.x 升级不需要迁移数据。

**macOS：桌面宠物重启后又会回来了**

1.16.20 升级了构建工具，连带升级的一个依赖改变了行为，导致启动时恢复宠物的那一步一直等不到结果：宠物不出现，也没有任何提示。只影响 1.16.20。已修复，并在正式构建上反复启动验证过。

**下载**

- 展开的下载任务完成或被删除后，顶上来的任务不会再自动展开——此前这会让点向某一集的操作落到别的任务上。
- 链接下载：解析失败后点"重试"，重试的是刚才那条链接，而不是重新读剪贴板。
- 链接下载：不带 `https://` 的链接（例如直接从地址栏复制的 `www.…`）现在可以解析；不是网页链接的内容会被明确拒绝。
- 多集任务的大小显示更准确：在所有分集的大小都已知之前，不再显示一个偏小的"总大小"。

**播放**

- 播放出错时的提示现在跟随界面语言，不再是英文。
- 电影的播放器标题不再带"立即播放"这类线路名后缀。
- 投屏到电视自动连播时，下一集不会再被误记成"快看完了"。
- 开着 App 不关超过一天后，再点之前看过的集不会再拿到已失效的播放地址。
- 详情页"继续观看"在跨片源续播时，也会跳过已经看完的那一集。

**其他**

- Windows：最大化按钮的图标会跟随窗口的实际状态。
- 设置页的几处报错提示改为跟随界面语言；导入备份选错文件时会明确说明。

**内部**

- 界面组件库迁移到 Flutter 官方的新包（旧的已被标记为弃用）。外观不应有变化；如果你发现哪里的按钮、对话框或菜单看起来和以前不一样，请反馈。

### 🐛 Known Issues

- 这一版同时包含界面组件库的整体迁移，是 1.16.x 里改动面最大的一次。macOS 版在正式构建上实际启动验证过主窗口、桌面宠物和播放器；Windows 和 Android TV 只验证了能构建，没有实际运行。如遇异常请退回 1.16.19。
- macOS：用系统菜单或绿色按钮进入全屏后，再用播放器自己的全屏按钮，两者可能反着来。请只用其中一种方式。
- macOS：开着桌面宠物时，宠物冒泡提醒的那一刻播放器的键盘快捷键会失效，点一下播放器即可恢复。
- 1.16.19 的投屏改动仍未在真实电视上逐一验证。如果换电视投屏时出现异常，请先手动点停止再投。
- 首次连接的三星电视可能配对不上并投屏失败，表现为电视上弹出的允许提示来不及点。重试一次通常可以。
- 投影仪和电视的 Miracast 不受支持（macOS 本身不提供这个能力）。请在设备上改用 AirPlay 或 DLNA 接收。

- Android TV：播放出错时屏幕上的"重试"按钮用遥控器按不到，需要返回后重新进入；片源列表里的"爱壹帆"在 Android TV 上无法使用。
- 投屏到 LG 或三星后，直接关电视或最后一集播完，App 仍会显示"正在投屏"，电脑也不会自动休眠。请手动点停止。
- 4 核及以下的 Windows 电脑默认在当前窗口播放（1.16.8 起）。如果播放异常，可在 设置 → 播放器打开方式 里改成"新窗口"。这条路径和近期的 Windows 改动都未在 Windows 真机上验证。
- 在当前窗口播放时，Windows 上没有最小化和关闭按钮，请用任务栏，或先点返回。
- 独播库上的追更只能靠浏览片库时发现更新，定期检查对它无效。
- 新装或系统更新后，第一次打开详情页可能卡一下（macOS）。这是渲染器首次编译着色器造成的，之后不再出现。
- 升级前收藏 / 看过的爱壹帆条目，封面图仍指向旧域名，可能显示不出来。
- LG 电视有间歇性的投屏失败：失败时电视上会弹出 "this file cannot be recognised"，这个框不关掉之后的投屏都会失败，需要用遥控器关掉再试。
- AirPlay 只在 macOS 上可用。
- Intel Mac 构建未经真机验证（开发机为 Apple 芯片）。
