### 🚀 What's New

**新增数据源：爱壹帆**

片源切换里多了一个「测试爱壹帆」。片库、筛选（分类／地区／年份）、搜索、详情、剧集、播放、下载都已接通。

这个站点的每一个请求都要签名，**包括每一个视频分片**——没签名的请求不会返回错误码，而是直接断开连接，所以症状看起来像网络故障而不是缺参数。播放列表由应用取回、逐条签好再交给播放器，这也是它能播的原因。

它的接口有访问频率限制：连续快速请求会被判定为异常访问并要求人机验证。所以剧集地址是**播放时才逐个解析**的，不会在打开详情页时把整部剧的地址一次性取完——一部 60 集的短剧那样做必然触发风控。

**数据源开关**

**设置 → 数据源**，每个源一个开关。关掉之后，该源的片库、片源切换、最近观看、想看、订阅都不再出现它。

记录**不会删除**，重新打开即恢复。至少要保留一个源。

下载不受影响：那些是已经存在硬盘上的文件，藏起来只会让你找不到自己的东西。

**底部状态栏显示各数据源延迟**

信号图标 + 毫秒数，当前源加粗，方便挑一个当下更快的。

延迟用 TCP 连接握手测量，不消耗任何接口调用——上面那个有风控的源，正是让这个取舍变成必须的原因。每次启动应用测一次，不定时轮询。

**播放器内核升级到 1.6.0**

新增按需解析播放地址、按源指定 HTTP 请求头，以及让缩略图和片头片尾扫描拿到真正在播的地址（此前它们拿到的是尚未解析的占位符）。

### 🐛 Fixed

- 详情页评分显示成 `4.6999999999999999`（浮点误差），现在保留一位小数。
- 爱壹帆的剧集标签显示成 `05`，现在显示 `第5集`。

### ⚠️ Known Issues

- 起播前有约 3 秒等待。播放器要等媒体时长连续多次读数稳定才开始播放（用于识别直播流），三个源都会经过这一步，尚未调整。
- 爱壹帆的视频流地址由站点按次签发、约两天过期，且解析在播放时进行，因此首次点击播放会多一次网络往返。
